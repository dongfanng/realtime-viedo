# Lucy → OBS → 微信 画面适配计划

## 背景与问题

使用 OBS 采集浏览器中 Lucy 返回的视频，再作为微信视频通话的虚拟摄像头输入时，因三方分辨率/比例不一致，微信聊天界面常出现**画面显示不全**或观感模糊。

微信官方未向普通用户提供视频通话分辨率调节入口；通话清晰度由微信自适应编码决定，主要受网络、采集源、通话类型与设备状态等影响，**不能指望在微信里调高分辨率来解决构图问题**。

## 目标

1. 微信视频预览中主体构图完整、比例正确（优先解决「显示不全」）。
2. 在微信画质上限内，尽量保证输入清晰、稳定。
3. 全链路使用同一宽高比，避免 OBS / Lucy / 微信各自裁切或留黑边。

## 核心原则

| 原则 | 说明 |
|------|------|
| 先定比例，再定像素 | 不必抠微信窗口精确像素；先对齐视频预览区宽高比 |
| 画布与浏览器同源比例 | OBS 画布与浏览器源宽高比必须一致，建议像素也一致 |
| 微信调不了分辨率 | 优化喂入端与网络，而非寻找微信内分辨率开关 |
| 比例正确优于堆高分辨率 | 720×1280（9:16）通常足够；盲目 1080p/4K 加重本机负担，对端未必更清 |

## 分辨率参考（页面 / OBS）

与 `src/main.js` 中 `ASPECTS` 保持一致：

| 比例 | 推荐像素（宽×高） |
|------|-------------------|
| 9:16 | 720×1280 |
| 3:4  | 720×960 |
| 4:5  | 720×900 |
| 1:1  | 720×720 |
| 4:3  | 960×720 |
| 16:9 | 1280×720 |

竖屏通话优先试 **9:16**；若仍裁切，可实测微信预览框宽÷高，改选最接近档位。

## 标准流程清单

1. **页面**：选择目标比例，勾选竖屏，连接 Lucy；确认状态栏输出尺寸接近所选像素。
2. **纯净模式**：按 `H` 隐藏控制面板与预览小窗，避免 OBS 采到 UI。
3. **OBS**：设置 → 视频 → 画布分辨率 = 上表对应像素；浏览器源宽高与画布相同；勾选 Enable media streaming。
4. **虚拟摄像头**：启动 OBS Virtual Camera。
5. **微信**：设置 → 通用 → 视频 → 摄像头 → 选 OBS Virtual Camera（改分辨率后建议重启微信更稳）。
6. **微调**：显示不全 → 查比例是否一致；人物被裁 → 调页面「裁剪缩放」(`zoom`)；黑边过多可反向调节。

## 问题分层与对策

### A. 构图 / 显示不全（比例问题）

| 环节 | 对策 |
|------|------|
| 页面 | `#aspect` 与竖屏开关；改后需重连 |
| 显示 | `#output` 默认 `object-fit: contain`；视口比例不对会缩图+黑边；纯净采集时可考虑 `cover`（会裁边） |
| OBS | 画布、浏览器源与页面比例/像素对齐；避免横屏画布硬塞竖屏；慎用拉伸 |
| 裁剪 | 调节 `zoom`（0=完整+黑边，100=裁满） |

### B. 清晰度 / 模糊（微信上限）

| 因素 | 对策 |
|------|------|
| 网络 | 双方尽量稳定 Wi‑Fi；弱网会动态降分辨率与码率 |
| 通话类型 | 优先 1v1；群视频官方规格通常更低 |
| 环境 | 光线充足、避免过热、必要时关美颜 |
| 输入 | 比例正确、主体居中、边缘留余量；不必过度推高 OBS 分辨率 |

若清晰度仍不可接受：可换腾讯会议/Zoom 等可选手动画质的通道，或用 OBS 本地录制 Lucy 输出（非微信通话场景）。

## 可选后续改造（代码）

- [ ] 纯净模式下 `#output` 使用 `object-fit: cover`，减少 OBS 视口与视频比例不一致时的黑边。
- [ ] UI 提示补全 **4:5 → 720×900**（与 `ASPECTS` 对齐）。
- [ ] 切换比例后自动提示或自动重连，避免 canvas 尺寸陈旧。
- [ ] 提供「一键复制当前推荐 OBS 画布尺寸」到剪贴板，降低配置出错。

## 验收标准

- [ ] 微信视频预览中人物/主体完整可见，无明显左右或上下被切。
- [ ] OBS 预览与微信预览构图基本一致（允许微信侧轻微再裁）。
- [ ] 稳定网络下通话可用，无因画布比例错误导致的拉伸变形。
